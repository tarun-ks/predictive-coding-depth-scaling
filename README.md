# Depth scaling of predictive coding inference

How many inner iterations does predictive coding need as networks get deeper?

This repository holds the instrumentation, analysis code and raw measurement data for a
depth-scaling study of predictive coding (PC) and its augmented-Lagrangian variant
(PC-ALM), measured against the reference implementation of Seely and Gould
([arXiv:2605.31022](https://arxiv.org/abs/2605.31022)).

## Scope

This adds **only instrumentation and analysis**. The implementation under study is not
vendored here: `setup.sh` clones it at the exact commit measured (`660747f6`, dated
2026-09-08) and links it into place. No update rule, energy or schedule in that package
was altered; every measurement is taken by an external caller.

## What it measures

| quantity | result |
|---|---|
| Activity-Hessian condition number, no training | κ ~ L<sup>2.024</sup>, CI [1.953, 2.095] |
| …repeated with 8 inputs per seed | κ ~ L<sup>2.036</sup>, CI [1.955, 2.116] |
| …on a convolutional stack | κ ~ L<sup>2.228</sup>, CI [1.929, 2.526] |
| PC inference budget vs depth | L<sup>1.916</sup>, CI [1.782, 2.050] |
| PC-ALM, refined ladder, 7 depths | L<sup>1.208</sup>, CI [1.175, 1.241] |
| PC with spectrum-set Nesterov momentum | L<sup>1.213</sup>, CI [1.156, 1.271] |
| Gradient-alignment budget, no accuracy criterion | L<sup>1.110</sup>, CI [0.951, 1.269] |
| Budget-grid systematic, from 4 offset ladders | ±0.066 |

The last three rows are the interesting part: an off-the-shelf accelerated inner solver,
given only the measured spectrum and nothing tuned, reproduces PC-ALM's inference budget
at every depth measured at refined resolution. The quadratic iteration count is a
property of the solver, not of the problem.

## Five things worth knowing before reusing this

**1. The condition number is a free proxy for inner-loop cost.** `kappa.py` needs no
training, no optimizer and no dataset pass, runs in seconds, and recovers the same depth
exponent a full training sweep does.

**2. A naive budget threshold will mislead you on an unstable solver.** Read with a
first-crossing criterion, the heavy-ball arm reports L<sup>1.083</sup> with an interval
containing exactly 1 — apparent ballistic propagation. It is an artifact: the iteration
touches the threshold and then diverges (80.9% at T=64 → 24.0% at T=96, L=64).
`refine_ttarget.py` implements the hold-window criterion that catches it.

**3. The momentum correspondence is not knife-edge.** Writing β = 1 − c(1−β\*) and
sweeping c from 0.5 to 2 leaves the budget unchanged on the coarse ladder at every value
tried (`results/beta_sens/`).

**4. A whole-network gradient cosine is output-dominated.** Split by layer quartile, the
input side needs 3× to 17× longer to reach the same alignment, and the gap widens with
depth. Do not read a global cosine as evidence that credit reached the input layers.

**5. Two obvious metrics are degenerate here, by construction rather than by bug.** A
constraint-residual threshold cannot gauge PC's convergence, because PC's equilibrium
residuals *are* its error signal and grow from zero. Distance-to-fixed-point inherits the
budget of the reference solve that defines the fixed point. Both are documented in
`REPORT.md`.

## Determinism

All runs are float32 on CPU with single-threaded XLA, parameters from an explicit
`PRNGKey(seed)`, and batch order a pure function of the seed. Re-running a cell
reproduces it bitwise.
